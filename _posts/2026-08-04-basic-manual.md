# 캐시
<hr>

## 캐시 동작 원리

가장 최근에 사용된 프롬프트는 우리 서버에 캐시로 저장된다. 따라서 동일한 프롬프트를 다시 사용하면 LLM을 거치지 않고 캐시된 결과를 가져오므로 즉시 차트가 생성된다. 예시 질문에 있는 문장 그대로 차트 생성을 누르면 곧바로 결과가 나오는 이유가 바로 이것이다. 이전에 누군가가 이미 한 번 실행했던 프롬프트이기 때문이다. 

캐시가 히트(Hit)되려면 이미 사용된 문장과 100% 완벽히 일치해야 한다. 따라서 다른 사용자가 입력한 문장과 토시 하나 틀리지 않고 일치할 확률은 낮으며, 주로 본인이 이전에 사용했던 프롬프트를 다시 재사용할 때 캐시가 작동한다. 이 캐시는 유지 시간(TTL)이 설정되어 있으며, 서버가 재시작되거나 주요 소스 코드가 변경되면 자동으로 초기화된다.

## 프롬프트 정규화 기준

서버는 사용자 프롬프트의 동일 여부를 판단할 때 텍스트 정규화 과정을 거친다. 입력된 프롬프트의 맨 처음과 마지막 공백을 제거하고, 문장 중간에 포함된 여러 개의 공백(탭, 줄 바꿈 포함)은 단 하나의 공백으로 합쳐서 비교한다.

따라서 아래의 1번과 2번은 정규화를 거치면 동일한 프롬프트로 인식되어 캐시를 사용하지만, 3번은 띄어쓰기가 달라 완전히 다른 프롬프트로 인식되므로 LLM을 새로 호출하게 된다.

```javascript
// 1번 프롬프트
통산 홈런 Top 10

// 2번 프롬프트 (중간 공백 여러 개)
통산 홈런 Top  10

// 3번 프롬프트 (띄어쓰기 다름 -> LLM 신규 호출)
통산 홈런 Top10
```


## 오염된 캐시 처리 및 우회 방법
간혹 잘못되거나 오류가 포함된 차트가 캐시에 저장될 수 있다. 애플리케이션 내부적으로 여러 단계의 검증 로직을 거쳐 LLM이 생성한 SQL의 결과가 부정확하다고 판단되면 재요청을 보내고, 끝내 해결되지 않으면 에러 메시지를 출력하도록 설계되어 있다. 하지만 간혹 이 검증망을 통과하여 잘못된 결과가 그대로 차트로 생성되는 경우가 발생한다.

한 번 차트가 생성되어 캐시에 등록되면, 동일한 프롬프트로 아무리 다시 요청해도 이미 오염된 캐시 결과만을 계속 보여주게 된다.

이런 경우에는 캐시를 우회하기 위해 프롬프트를 요청할 때 한 글자라도 다르게 입력해야 한다. 문장 마지막에 마침표(.)를 하나 찍는 것만으로도 충분하다. 프롬프트가 달라지면 서버는 캐시를 건너뛰고 다시 LLM을 호출하여 차트 생성을 시도한다. 동일한 의미의 프롬프트라 할지라도 다른 SQL이 생성될 수 있는 이유는 기본적으로 LLM이 확률적(stochastic and non-deterministic)으로 작동하기 때문이다.

# 실제로 LLM을 호출하는 시점
<hr>

서비스 전체 흐름에서 실제로 LLM을 호출하는 순간은 차트 생성 버튼을 클릭하고 캐시 히트에 실패했을 때, 오직 이 한 가지 경우뿐이다.

화면 상단의 슬라이더를 움직여 연도를 변경 하는 작업은 LLM을 전혀 거치지 않는다.  그렇기 때문에 반응 속도가 매우 빠르다.

심지어 차트 공유 기능으로 생성된 URL 링크나 임베드(Embed) 차트 역시 LLM을 타지 않는다. 공유 URL과 임베드 소스 자체에 SQL, 차트 종류, 제목 등의 모든 메타데이터가 포함되어 있기 때문이다. 특히 임베드 차트의 경우 앞단의 CDN(Content Delivery Network)에 캐시로 저장되므로, 설령 우리 서버가 다운되어 있는 상태라 할지라도 CDN 캐시가 만료되기 전까지는 차트가 정상적으로 표시된다.

LLM을 호출할 때마다 API 토큰 비용이 발생하고 응답 속도가 느려지므로, 이러한 구조를 통해 LLM 호출을 최우선으로 절약해야 한다.

## 차트 종류 지정

기본적으로 프롬프트에 원하는 차트 종류를 직접 지정할 필요는 없다. LLM이 데이터 구조를 분석하여 가장 최적의 차트 유형을 자동으로 결정해 준다.

하지만 사용자가 의도한 차트 종류로 나오지 않을 때는 프롬프트에 차트 종류를 명시하여 제어할 수 있다. 예를 들어 `손아섭 연도별 안타 추이` 라는 동일한 프롬프트를 입력하더라도, LLM의 비결정적 특성 때문에 어떤 때에는 선(Line) 차트로 나오고 어떤 때에는 막대(Bar) 차트로 나올 수 있다.

특정 차트로 고정해서 보고 싶다면 프롬프트 뒤에 `선 차트`, `라인 차트`, `막대 차트` 등으로 원하는 형태를 명시하면 된다. 다만 데이터의 성격과 맞지 않는 차트는 지정하더라도 적용되지 않는다. 예를 들어 산점도(Scatter) 차트는 변수 간의 상관관계를 나타낼 때 사용되므로, 단순 추이 데이터에서는 프롬프트에 명시하더라도 적용되지 않는다.

## AI

선동열을 선동렬로 오타를 내어 입력해도 맥락을 파악하고 정상적으로 차트를 생성하며 이름까지 올바르게 교정해 준다. 만든 나도 놀랐다.

또한 `이승엽 연도별 홈런 추이`라고만 입력하면 동명이인 선택 안내가 발생하지만, `삼성 이승엽` 또는 `라이온즈 이승엽`과 같이 소속 팀이나 애칭을 함께 적어주면 정확히 해당 선수를 식별하여 처리한다.

다만 이 서비스의 프롬프트 입력창은 일반적인 챗봇 형태와 달리 단발성 쿼리로 작동하므로, 방금 전에 입력했던 이전 프롬프트의 맥락을 기억하는 메모리 기능은 전혀 지원하지 않는다.
